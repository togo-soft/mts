### C2. engine: `Close()` 中关键资源关闭错误全部被忽略

**位置**: `internal/engine/engine.go:265, 277, 281`

`FlushAll()`、`wal.Close()`、`flusher.CloseAll()` 三个关键操作的错误均被 `_` 忽略。刷盘失败意味着内存数据丢失，WAL 关闭失败可能导致日志数据丢失。

**修复建议**: 使用 `errors.Join` 收集所有错误并返回。

### C3. shard: `Shard.Close()` 中 `err` 变量从未赋值

**位置**: `internal/storage/shard/shard_lifecycle.go:17-35`

`err` 变量声明后，在 `closeOnce.Do` 闭包内从未被赋值，即使 `compaction.Stop()` 或 `levelCompaction.Stop()` 失败，`Close()` 始终返回 `nil`。

**修复建议**: 在闭包内捕获所有 stop 错误并赋值给 `err`。

### C4. shard/sstable: `CompressBlock` 压缩错误被静默忽略，导致数据丢失

**位置**: `internal/storage/shard/sstable/writer_encode.go:36, 67, 164, 201, 223`

`compressed, _ := CompressBlock(blockData, w.compressAlgo)` 忽略错误。若压缩失败返回 `nil`，后续 `append(encoded, compressed...)` 不追加任何数据，整块数据从 SSTable 中静默丢失。

**修复建议**: 所有 5 处调用点必须检查并处理错误。

### C5. shard: `RetentionService.Stop()` channel 双关 panic 风险

**位置**: `internal/storage/shard/retention.go:72-80`

`select/default` 模式存在 TOCTOU 竞态。两个 goroutine 并发调用 `Stop()` 时，可能同时通过 `default` 分支，导致 `close(s.done)` 双关 panic。

**修复建议**: 使用 `sync.Once`。

### C6. shard/sstable: `lookupFieldIdx` 可返回 -1 导致数组越界 panic

**位置**: `internal/storage/shard/sstable/writer_field.go:262-268`

`lookupFieldIdx` 可能返回 -1，后续 `w.fieldIdxNames[idx]` 直接使用会产生 out-of-range panic。虽然理论上字段发现后不该发生，但对损坏数据缺少防御性检查。

**修复建议**: 添加边界检查，返回 error 而非 -1。

## 二、High 级别问题

### H1. engine: WAL 截断错误被静默忽略，可导致数据重复

**位置**: `internal/engine/engine.go:239`, `internal/engine/flush_coordinator.go:134`

两处 `TruncateBefore` 错误被忽略。若截断失败，WAL 段不被删除，重启时会重复 replay 已刷盘数据。

**修复建议**: 至少记录错误日志，或在必要时返回错误。

### H2. engine: `Flusher.Flush` 错误被静默忽略

**位置**: `internal/engine/flush_coordinator.go:117`

`fc.flusher.Flush(passive)` 错误被 `_` 忽略。Flush 失败可能导致数据只写入了 unordered 但未被 shard 管理器处理。

**修复建议**: 处理该错误，至少记录日志。

### H3. engine: `ListFiles` 错误被忽略，反压条件可能误判

**位置**: `internal/engine/flush_coordinator.go:89`

`unordered.ListFiles(fc.dataDir)` 错误被忽略，导致 `files` 为 `nil`，反压条件 `len(files) >= maxUnorderedFiles` 永远为 `false`，反压机制失效。

**修复建议**: 在目录不可访问时跳过 flush（保守策略）。

### H4. engine: `createDataIterator` 使用 `context.Background()` 而非调用方 context

**位置**: `internal/engine/engine_query.go:294`

即使调用方取消了上下文，数据迭代器的创建和耗时操作仍会继续执行，无法响应取消请求。

**修复建议**: 接受 `ctx` 参数并传递给下游。

### H5. shard: `RegisterSSTable` 中 `os.Rename` 错误被静默忽略

**位置**: `internal/storage/shard/shard.go:269`

SSTable 文件重命名失败后文件停留在错误位置，对 compaction 不可见，且无任何日志或错误返回。

**修复建议**: 处理重命名错误，至少记录日志。

### H6. shard: `writeSSTableWithTimeout` 超时后 goroutine 资源泄漏

**位置**: `internal/storage/shard/shard.go:161-231`

5 秒超时后主 goroutine 删除文件并返回，但后台 goroutine 继续执行写操作，可能产生孤立 SSTable 文件。

**修复建议**: 传递 `context.Context` 到 Writer 使 I/O 可取消，或添加孤儿文件清理机制。

### H7. shard/sstable: 字段名注入 — 路径遍历风险

**位置**: `internal/storage/shard/sstable/writer_field.go:48-50`

字段名来自解析的数据，若包含 `/`，`filepath.Join` 会创建子目录或逃逸预期目录。虽然 `SafeOpenFile` 检查了 `..`，但不阻止 `/`。

**修复建议**: 验证字段名不含路径分隔符。

### H8. shard/sstable: `NewMergeIterator` 静默跳过打开失败的文件

**位置**: `internal/storage/shard/sstable/merge_iterator.go:93-109`

`NewReader` 或 `NewIterator` 失败时错误被静默跳过，无法诊断数据丢失。

**修复建议**: 至少记录警告日志。

### H9. metadata: `GetTags` 返回内部 map 引用，存在并发安全问题

**位置**: `internal/storage/metadata/series_simple.go:153-161`

`GetTags` 直接返回内部 `map[string]string` 引用，调用方可修改内部状态。即使有 `sync.RWMutex`，锁在返回前释放。

**修复建议**: 返回防御性拷贝 `copyTags(tags)`。

### H10. api/gRPC: `CreateDatabase` 错误被静默忽略

**位置**: `internal/api/grpc.go:292`

`s.engine.CreateDatabase(...)` 的错误返回值用 `_` 丢弃。若数据库创建失败，客户端收到成功响应，数据完整性受损。

**修复建议**: 检查并返回错误。

### H11. compaction: `sync.WaitGroup.Go()` 方法不存在

**位置**: `internal/storage/compaction/compaction.go:542`, `internal/storage/compaction/level.go:592`

标准 `sync.WaitGroup` 没有 `Go()` 方法。若这些代码被执行将导致编译错误或运行时 panic。

**修复建议**: 替换为标准模式：`wg.Add(1); go func() { defer wg.Done(); ... }()`。

### H12. compaction: `UnorderedCompactor` 丢弃部分读取数据

**位置**: `internal/storage/compaction/unordered_compactor.go:86-89`

当 `ReadAll` 返回 `err != nil && len(rows) > 0` 时，所有数据被丢弃，可能造成静默数据丢失。

**修复建议**: 处理部分成功读取的数据。

### H13. compaction: 源文件删除错误被忽略，可导致数据重复

**位置**: `internal/storage/compaction/unordered_compactor.go:157`

`os.Remove(file)` 错误被 `_` 忽略。删除失败导致下次 `Compact()` 重复处理。

**修复建议**: 返回错误或至少记录日志。

### H14. downsample: `markDownsampleDone` 创建文件未指定权限

**位置**: `internal/storage/downsample/downsample.go:411-415`

使用 `os.Create()` 创建标记文件，权限取决于 umask，可能产生 world-readable 文件。项目要求文件权限为 0600。

**修复建议**: 使用 `os.OpenFile(path, os.O_CREATE|os.O_WRONLY, 0600)`。
